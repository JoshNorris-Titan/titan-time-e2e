# Scripts that run-tests.sh should SKIP when running against a remote
# environment. One basename per line; # starts a comment.
#
# Deliberately near-empty. A static read of the suite found FEWER environment
# couplings than expected:
#
#   * nothing hardcodes localhost — the two scripts that mention it use the
#     overridable default ${TT_BASE_URL:-http://localhost:8080};
#   * the mail tests read the app's own Emails Sent admin page, so they need no
#     external catcher and no extra secret — only an administrator login, which
#     every environment already has. They fail loudly at tt_mail_prepare if that
#     page cannot be opened;
#   * the TT-654 MCP tests hit an in-app endpoint via TT654_MCP_PATH, not a
#     local process, so they work anywhere the module is deployed;
#   * the bookend clear tests are scoped to TT_E2E_CONSULTANTS and explicitly
#     leave non-e2e data alone, so they are safe on a shared environment.
#
# What can still legitimately fail on cloud dev is CONFIGURATION rather than
# portability — e.g. verify-unittests needs UnitTesting.RemoteApiEnabled set on
# the target environment, and the TT-654 tests need that module deployed with
# the right constant. Add entries here as the first cloud runs reveal them,
# with a one-line reason each, rather than pre-emptively.

# verify-scheduled-event-config reads the Mendix model on disk. The suite is its
# own repository, so the model is not checked out beside it in CI and the step
# cannot run there. It is the one step that needs no app at all, so run it
# locally instead - it is fast and needs nothing deployed.
verify-scheduled-event-config.test.sh

# verify-mirrored-regions runs the comparator that lives in the MODEL repo
# (tools/check_mirrors.py), which is not checked out beside this one in CI. Same
# shape as verify-scheduled-event-config above. The test deliberately fails rather
# than self-skipping when it cannot find the comparator, so the exclusion is
# visible here instead of hiding as a silent green. Run it locally, where the
# model repo is the parent directory - it needs no browser, login or seed data,
# so it costs about a second. Note this leaves CI blind to mirrored-region drift;
# the real gate is /pre-commit-check, which runs the same comparator before every
# commit, and drift can only arrive through a commit.
verify-mirrored-regions.test.sh
